Computes `windowMinute = Math.floor(Date.now() / 60000)` and issues a single atomic `INSERT INTO rate_limit (ip, window_minute, count) VALUES (?, ?, 1) ON CONFLICT(ip, window_minute) DO UPDATE SET count = count + 1 RETURNING count` round trip; reads `count` from `result.rows[0].count`. ## Requirements Traced

- **R10#2 (Turso-table rate limit, 30/min, Retry-After)** — `INSERT ... ON CONFLICT ... DO UPDATE SET count = count + 1 RETURNING count` performs the increment + read in one round trip, matching the design's atomicity goal across edge nodes. `allowed` flips at `count > 30`. `resetInSeconds` is clamped to a minimum of 1 so the caller's `Retry-After` header never reads `0` mid-window. GC sweep keeps the table bounded without coupling to request latency (swallowed errors).
