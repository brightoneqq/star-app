## Requirements Satisfied

- **R1#1** — A "提交本卡" button is injected per scored card via `injectCardSubmitButtons` (visibility is mode-gated by the CSS rule added in task 1; JS-level lifecycle hook is task 5's responsibility).
- **R1#2** — Button uses the CSS class `quiz-submit quiz-submit--card`, inheriting the navy CTA from `.quiz-submit` and the compact variant styling from task 1.
- **R1#3** — Button is wired with `MyStar.addTapListener` (via the `M` alias) — the project's single tap-binding entry point — not `addEventListener('click', ...)`.
- **R1#4** — Button label is the literal string `'提交本卡'` set via `btn.textContent`, matching the spec.
- **R2#1** — Grading uses the shared `gradeScope(cardEl)` from task 2, scoped to the current card. No duplicate grading logic.
- **R2#5** — Per-card score is persisted via `M.writeNumber('quizScore_' + SLUG + '_' + cardEl.id, result.score)` — the `_<slug>_<cardId>` key pattern.
- **R2#6** — Per-card submit handler does NOT write the aggregate `quizScore_<slug>` and does NOT write `quizTime_<slug>`. Per-card submission has no side effects on the unit-level aggregate.
- **R3#1** — Per-card submit affects only the originating card: the handler calls `gradeScope(cardEl)` (card-scoped grading), `updateCardBadge(cardEl, …)` (badge update on the same card), and writes only the per-card storage key for that `cardEl.id`. No other DOM is mutated.
- **R3#2** — No banner is shown by the per-card handler — `showBanner` is never invoked from this code path. The unit-level banner stays exclusive to the unit-level submit flow.
- **R3#3** — Badge on the originating card is refreshed in place via `updateCardBadge(cardEl, result.score)` immediately after grading, before control returns from the tap handler.
- **R3#4** — Per-card submission is idempotent: tapping the button repeatedly recomputes the same card's score, overwrites the same storage key, and updates the same badge span (since `updateCardBadge` is idempotent per task 3). Wrapper injection is also idempotent — the early return on existing `.quiz-card-submit-wrap` prevents stacking.
- **R3#5** — Intro/note cards (cards with zero `.blank` children) are skipped — no button is injected, so they cannot be submitted.
- **R6#3** — Per-card submit does not invoke `showBanner` and does not touch the unit-level banner DOM — `removeCardSubmitButtons` only removes `.quiz-card-submit-wrap` wrappers. Banner lifecycle remains under unit-level control.
